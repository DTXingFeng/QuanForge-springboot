| 跟踪ID | 品种 | 记录的卖出限价 | 该分钟最高成交价 | 按限价OHLC模型能否判定该分钟入场 |

## 已启动的实时报价实验

进程在本地Windows运行，读取树莓派新信号，HTTP仅允许Bybit公共行情GET。没有交易凭证、账户下单代码、新AI推理请求、生产部署或历史账本写入。

- 注册时源记录水位为836；不导入已有ACE跟踪，不追补历史交易。
- 只接收注册之后产生、收到时不超过90秒的新PAPER信号。原始信号含ID、版本和价位并保存；AI内部完整行情快照未提供，不能据此认证AI全部工具的时间一致性。
- 两个独立的20U虚拟账户成对比较：`source_exit` 使用收到时的SL/TP，`profit_protect` 在观察到1R浮盈后移至估计成本保本线，在1.5R后以0.75R回撤保护。两者共同持仓TTL60分钟。
- 只有两组都空仓才接收下一对；共同使用较低余额反推同一数量。初始单笔计划损失上限约0.2U，名义仓位最高约1倍账户资金，模拟杠杆5×。两个对照账户不能相加当作一个40U组合，也不代表实际投入资金。
- 使用公开最优bid/ask、该档数量、价格步长和数量步长。BUY必须在ask加不利滑点后仍不超过限价；SELL必须在bid减滑点后仍不低于限价，才记模拟入场。始终只是模型成交，不是交易所实际成交。
- 每次止损只按之后实际观察到的bid/ask退出，加不利滑点并按不利方向取整；不使用历史K线极值倒填止损成交。
- 基础假设为每边手续费0.055%、不利滑点0.05%；持仓跨资金费时点而缺少实际结算证据，则净收益保持未知。
- SQLite持久化源水位、订单事件、持仓、保护价、费用与现金；原子提交，重复报价不重复开仓，乱序报价不执行后来才建立的保护。独占写锁阻止第二个进程同时写入。
- 名义轮询间隔5秒，但HTTP和SSH耗时会增加间隔；它不是5秒止损执行保证，更不是毫秒级撮合。网络失败保留错误，不伪造成交；断流后可能发生更差的观察退出。
- 01:47:36之后停止新增入场，01:57:36按新鲜报价作预登记的实验结束平仓；若取不到新鲜报价，保留未平模拟状态并标记，不编造平仓。

该对照只研究“同一批新AI信号，在正确报价、成本和不同退出规则下会怎样”，不是完整复制生产模式切换、反转取代、LLM持续改仓或多策略账户。浮盈保护也可能过早退出错失收益，不能凭设计认定它优于对照。
