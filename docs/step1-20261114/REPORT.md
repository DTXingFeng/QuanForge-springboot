## 复现与最小修复

失败测试见 [timeout-before.txt](timeout-before.txt)：模拟委托已受理但响应丢失，旧代码实际保存为 PAPER，断言要求 DEMO 而失败。这是工程行为复现，不能用它估算真实账户有多少亏损由该缺陷造成。

本次修改：

1. 发请求前，独立提交 DEMO/PENDING 行及固定 `orderLinkId`；账户保留 `demo_slot`。入场与结算方法暂停调用者事务，使外部请求不包在原来的长数据库事务里。
2. 初始提交失败就禁止发单。响应或后续数据库写入失败时，已提交意图继续存在，不回退 PAPER，也不把撤单 ACK 当作成功补偿。
3. 待核对记录通过固定编号查 history/realtime，校验返回行的品种与身份。找到后补回 orderId/数量，继续原有持仓保护。查不到时保留未知，不视为未下单或零风险，不自动重下。
4. 唯一数据库约束限定该配置账户同时只有一个新执行路径持有者；同进程入口和结算串行。任何活跃 Demo 记录还会阻止新增风险，即使自动下单已经关闭。反向建议不再直接触发 Demo 换仓。
5. 明确终态后释放保留位；补齐 `PartiallyFilledCanceled`、`Deactivated` 的终态处理。

这是保守的单仓限制，不是已经实现多策略资金预算。策略信号、指标参数、手续费假设和历史交易没有为了改善收益而调整。没有运行策略收益对照；此次验收对象是订单责任。
