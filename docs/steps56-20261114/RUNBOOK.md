# QF-S 候选发布与回退说明

版本 `v4.8.7-audit-20261114`。状态：候选包，尚未获准进入交易所自动 Demo。包内不含生产数据库、私有 application-local 配置、密钥或旧部署 JAR。

## 已准备的内容

候选 JAR、当前构建的 React 静态页面、一次性迁移 SQL、文件哈希及源码指纹。账户 POST 默认关闭；调度器可通过 `--app.scheduling.enabled=false` 关闭。该开关会同时停止 AI 扫描、持仓定时管理、孤儿保护、新闻和 Telegram 定时任务，不能带着无人接管的仓位启动观察模式。

候选包的只读启动参数还必须显式包含 `--app.execution.account-writes-enabled=false`。不要为了通过验证而设置 true；它也控制平仓、撤单及保护单写操作。已经有仓位时，需要先安排可验证的管理接管，不能仅关写或杀进程。

本地隔离观察启动示例（必须是新的测试目录和数据库）：

```text
java -jar quanforge-candidate.jar --server.address=127.0.0.1 --server.port=40876 --app.scheduling.enabled=false --app.execution.account-writes-enabled=false --spring.datasource.url=jdbc:sqlite:observer.sqlite --spring.jpa.hibernate.ddl-auto=update
```

不要将这个数据库 URL 换成生产库来做启动测试。通过 `/api/bybit/mode` 只能确认本地模式，不能证明交易所连通、账户身份或保护单实际生效。

## 实际部署前必须补齐

1. 对照 manifest 核对候选 SHA256、当前部署 SHA256、源码和测试指纹；重新在线备份数据库，并核对正在运行的所有交易出口。
2. 以只读接口明确 Java 与影子程序各自账户，独立核对全部仓位/委托及分页完整性。Java 空仓不能代替影子账户空仓。
3. 完成显式凭证映射、持久化退出命令与逐笔结算归属、统一行情时点、保护单和异常接管的验收。当前均不能由本地测试替代。
4. 在副本执行迁移，核对历史数量、关键字段、唯一索引与 integrity_check。若已应用过旧迁移，不得再次 ALTER；应基于实际 schema 编写并审阅差异迁移。
5. 待这些技术门槛通过后，提交确定的服务停启、文件切换和模拟订单范围供使用者确认。本轮没有执行上述操作。

## 获准后的发布顺序

先阻止新增风险并确认旧仓保护/所有权接管；保留原 JAR、配置与数据库快照。只在批准的维护窗口原子替换指定 JAR，先以无账户写操作、无调度的观察模式检查启动和模式；核对数据库及日志后，再按单独批准的模拟订单验收方案验证接口。不能直接恢复 100 倍杠杆、多策略或 AI 自动改仓。

应用私有配置从候选资源中排除；生产解密主密钥必须继续由其已有的外部配置提供。不得生成新密钥去“修复”旧库解密错误，也不得将本地示例密钥作为生产解密来源。

## 回退顺序及边界

当前部署原 JAR 已只读保存到私有取证目录，SHA256 为 `980b07de865cbb6714f64dc9cb90847c2cc8670b6dcd146ee9f4258a4dbf697d`。它可能含原私有配置，因此没有放进候选 ZIP 或公开目录。

回退前仍要暂停新增风险并安排已有仓位接管。保存失败版本产生的数据库及日志，再恢复同指纹的旧 JAR 和原配置。**不能覆盖回写旧数据库快照**，否则会丢掉维护后新增交易历史；也不能通过删新列、新表来回退。迁移仅增加可空字段、索引及观察表；已在副本检查行数和完整性，但旧版本在迁移库上的所有业务行为仍须独立验收。

回退到旧 JAR 也意味着重新暴露旧执行缺陷，必须保持旧配置中的自动下单关闭。若存在未知委托或仓位，不得将“进程成功启动”当作回退完成。

## 测试口径

单元/隔离数据库测试、候选 JAR 的本地观察启动、树莓派实际部署、交易所订单验收分别记录。只有前两项在本轮执行；候选包不提供实盘或盈利认证。
