## 部署影子订单的高优先级问题

部署副本的 `demo_call` 在一个代理请求超时之后会尝试第二出口，包括 POST。外层 `demo_order` 虽声称只对“连接未建立”重试，内层已先重发，保护失效。下单没有 orderLinkId；超时无法判断是否已成交，存在重复单风险。

`demo_open` 只有市价 IOC，没有交易所 SL；止损仍由小时 bar 确认后才调用平仓。`reconcile` 按 symbol 获取账户整仓并平仓/重开，没有订单所属策略隔离；同币种手动仓或其他策略仓会被干预。配置中的 base 未限制为 api-demo.bybit.com，不能因命名为 Demo 就视作强制 Demo 门禁。这些均为源码确认的风险，未据此推算实际亏损比例。

已交付 `deployed-v5-safety.patch`，对**快照部署源码**最小加入 fail-closed 锁：阻止 `demo_call` 的所有签名请求以及 `demo_open` 的前置网络查询。该补丁不是完整影子执行器改造，也不声称实现了幂等/保护单/所有权；它在这些功能验证前关闭影子执行。`test_deployed_v5_safety.py` 实际将补丁应用于临时部署副本，再把两个 opener 替换为禁止网络 mock，验证 GET/POST、开仓、平仓、对账和余额入口均无网络调用。结果见 `deployed-v5-safety-test.txt`。**生产未应用此补丁。**

部署 `v5_guard.py` 根据权益或最近20笔均值直接 `systemctl stop quanforge-v5mech`，不检查纸面 OPEN/Bybit 剩余仓，也不接管保护。快照 v5 42 条记录全部已结算，OPEN=0，故本次不能声称 guard 已造成遗留仓位；这是已确认的停机机制缺陷和未观测到实际损害的风险。

## 实验复现与解释

```powershell
python -m unittest discover -s tools/tests -p test_paper_engine.py -v
python tools/audit_paper_replay.py
python tools/tests/test_deployed_v5_safety.py --source .audit-private/qfs-audit-20261112-0805/tools/paper_v5mech.py
python tools/audit_historical_exit_replay.py --snapshot .audit-private/qfs-audit-20261112-0805
```

`python-replay.json` 有正常、快速上涨/下跌、极端跳空、断线、重启、API超时、重复响应、缺失及乱序十组场景，每组基线/修复使用相同 bars、入场/SL、参数和成本。基线从固定 Git commit 直接加载；修复从工作区加载；入口均被 mock。每轮默认 $200 权益和入场名义金额，外置统一成本假设为往返手续费 $0.22、滑点 $0.08，资金费未知（null），不是账户费率实证。

断流场景原代码漏掉 stop，24h 后以零毛收益退出；修复正确记 -$2，净假设 -$2.30。历史账本退出 bar 延迟从1440分钟降为0，但**实际恢复检测仍发生在断流结束，合成场景为180分钟之后**。JSON 分开输出账本退出时点和观察时点，不能把回填历史记账当实时止损改善。跳空场景由 -$2 变 -$10、毛权益回撤1%变5%；这是更保守真实的记账，不是更赚钱。快速单边 TTL 从错误25h改24h，示例毛收益由$25降$24。

`historical-exit-replay.json` 合并所有只读 `history*.sqlite`（输入SHA-256列在输出），使用快照 v5 原 entry/SL 和新取得的真实1m OHLC，只聚合完整连续60分钟成小时；历史旧 created_at 被明确解释为信号 bar 开盘，假设实际入场在+1h收盘。冻结信号为 MIXED、WARMUP=1以隔离退出路径；固定$200敞口、相同外置成本。每笔独立重置，不把各笔盈亏简单累加当组合收益。42/42条均有可用退出窗口，基线/修复、每小时/每4小时轮询四组合计168次。它是**真实行情上的工程退出实验，不是完整策略回测**。

## 仍未达到稳定模拟盘标准的部分

部署shadow关闭补丁同样阻止影子平仓/对账，只能在独立确认该影子账户无在场仓位后用作隔离，不能当作带仓位紧急接管方案；Java配置账户当前零仓位不足以证明影子配置为同一账户。

- v5仍是已完成小时 bar 驱动的纸面估计；盘中触及SL至小时收盘可延迟近一小时，另加轮询和网络延迟；即使回放补齐也不能追溯执行真实影子平仓。
- 账本收益仍为 gross；没有逐笔实际费用、资金费、量化滑点/成交队列。旧数据不能反推真实净收益或真实仓位。实验成本是明确假设，不作为原账户扣费归因。
- trendrule 的 pending、冷却、90分钟亏损熔断仍未完整持久化；重连热身没有逐 bar 执行持仓管理；权益更新和OPEN行不是一笔事务；风险/eq sizing仍使用结算权益。此次没有为已停用策略重写状态机。
- backtest与前向趋势EMA热身长度、退化ATR门槛等仍不完全一致；原backtest模块导入时加载生产模型，完整回测需有效模型文件，默认输出还会清空目标回测表。此次仅做语法验证及对应撮合公式同步，未冒称完整回测已跑通。运行其他脚本前必须选新输出文件，禁止覆盖真实历史。
- 没有证明 v5/趋势策略具有出样本优势；已有研究按全历史选币/参数、信号有重叠，并存在多个臂位选择，不能把筛选后均值当后验无偏预测优势。

结论：已验证若干会扭曲亏损/持仓管理的工程缺陷，并提供本地最小修复、可复现实验和部署影子执行的关闭补丁。修复成功不等于策略盈利；当前远程部署和未修复边界不支持恢复无人值守影子交易。
